BACKEND AUTONOME — CORRECTION DU PAQUET DASHBOARD
13 novembre 2026 — aucun déploiement

Défaut : deux accès du backend à ../../src/utils/dashboardPrescriptionSummary.js.
Le fichier existait dans le dépôt de développement mais pas dans l'archive backend.
Le cache disque importait ce fichier dès son chargement, même désactivé ; la
construction d'un résumé l'importait aussi à la demande. Ces erreurs remontaient
comme client-list-summary-unavailable sur l'API du Dashboard.

Correction : source pure unique dans backend/utils/dashboardPrescriptionSummary.mjs.
Le frontend réexporte ce contrat depuis son utilitaire existant ; le backend
l'importe localement et calcule son empreinte locale. Aucune copie divergente du
calcul. Les règles d'autorisation, historiques, projections et écritures métier
restent inchangés. La persistance disque n'est pas activée sur des données réelles.

Test ajouté : npm run test:backend-package, appelé par deploy.sh dans preflight.
Il extrait et exécute uniquement le bloc exact de construction d'archive présent
dans deploy.sh. Pas d'exécution de deploy.sh, de SSH ou de commandes distantes.
L'archive est extraite dans un répertoire jetable sans src ni node_modules.
Les secrets exclus par le script sont vérifiés absents. Deux contre-tests
réintroduisent les anciens chemins uniquement dans cette copie et doivent échouer.
Le paquet corrigé doit produire les résumés exacts, préserver les historiques et
fonctionner avec cache désactivé, cache vide et cache repris dans un autre processus.

Qualification supplémentaire de l'API :
PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH firebase emulators:exec --config firebase.performance-test.json --project demo-byl-performance --only auth,firestore 'node scripts/testBackendPackage.cjs --emulators --installed-dependencies'

Les dépendances locales sont vérifiées contre les versions de l'archive lockfile,
puis copiées physiquement (sans lien vers le dépôt) dans le paquet isolé. Le mode
par défaut --emulators propose aussi un npm ci hors ligne. Celui-ci n'a pas pu
aboutir ici, car proxy-addr manquait au cache npm. Le téléchargement npm a été
refusé par la revue automatique ; aucune tentative de contournement réseau.
La qualification a donc utilisé les copies locales conformes, pas une nouvelle
installation depuis le registre. Cette limite est distincte de l'autonomie du code.

et ses transactions Firestore ont été testés depuis le paquet avec 12 dossiers,
